# 自分のマシンでページを開く（`web` コマンド）

自分の VM にはブラウザが入っていて、`web` という入口が用意されている。
**検索で足りないとき**（ページの中身を読む／表を拾う／スクリーンショットが要る）に使う。

## いつ使う
- Firecrawl の検索要約や本文では足りない（JS の表・一覧・画面が要る）
- 画像として見たい（スクショを撮って自分で確認する）
- ログインなしで読める普通のページ

## 手順
```bash
# 本文を読む（既定 4,000 字。JS が多いページは --wait を 2,000〜4,000 に）
web text "https://example.com/article" --chars 6000 --wait 2500

# スクリーンショット（自分のホームに保存される）
web shot "https://example.com" shot.png --full

# ページ内のリンク一覧（最初の 40 本）
web links "https://example.com"

# JS を 1 行だけ評価（タイトル確認など）
web eval "https://example.com" "document.title"
```

## 完了条件
- `web text` なら**本文の一部が実際に印字されている**（「読んだ」と言う前に、出力をそのまま自分の言葉に使う）
- `web shot` なら `saved: …` が出て、そのファイルが存在する
- 失敗したら stderr の `web: …` をそのまま報告する（推測で埋めない）

## 失敗時
- `Timeout` ⇒ `--timeout 60000 --wait 4000` でもう一度。それでも駄目なら「開けなかった」と書く
- `ERR_NAME_NOT_RESOLVED` ⇒ URL の綴りを疑う（検索で正しい URL を確認）
- 中身が空 ⇒ JS 描画のページ。`--wait 4000` を足す。それでも空なら「JS で描かれていて読めなかった」と書く
- 何も出ない／`web: ...` だけ ⇒ `web text` の引数（URL を引用符で囲む）を見直す

## 注意
- **やっていないことを「読んだ」と書かない**。出力を貼るか、要点を自分の言葉で書く
- ログインが要るページ・有料記事は開けないことがある。その場合は素直にそう書く
- 1 回の活動で開くのは 3 ページまで（同じサイトを何度も往復しない）
